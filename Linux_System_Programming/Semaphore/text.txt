🔐 Semaphore in Linux System Programming (C)
1. What is a Semaphore?
A semaphore is a synchronization mechanism used to control access to shared resources and coordinate multiple threads or processes.
Think of a parking area with 3 available spaces. 🚗
- When a car enters, one space becomes occupied.
- When a car leaves, one space becomes available.
- If all spaces are occupied, another car must wait.
A semaphore works similarly by maintaining a counter that represents available resources or signals.





2. Why do we use a Semaphore?
Semaphores are useful when multiple threads or processes need to coordinate their work.
Common uses:
- 🧵 Synchronizing multiple threads.
- 🏭 Controlling access to a limited number of resources.
- 📦 Producer-consumer problems.
- 🔔 Signaling between threads or processes.
- ⚙️ Coordinating processes in Linux System Programming.




3. Types of semaphores

1. Binary Semaphore
Its value is 0 or 1. It can be used for signaling or coordinating access to a resource.
Example: Notify a consumer that data is ready.




2. Counting Semaphore
Its value can range from zero to a positive number. It tracks how many resource slots are available.
Example: Allow up to 3 threads to use a resource simultaneously.



Semaphore vs mutex: A mutex has an ownership concept: the thread that locks it should unlock it. A semaphore does not have the same ownership rule and is often used for signaling between threads.
4. How does a semaphore work?
Two fundamental operations are used:
Operation	Meaning
sem_wait()	Decreases the semaphore value; waits if no resource is available
sem_post()	Increases the value and can wake a waiting thread
For a counting semaphore initialized to 2:
Initial value = 2

Thread 1: sem_wait()  → value = 1
Thread 2: sem_wait()  → value = 0
Thread 3: sem_wait()  → waits

Thread 1: sem_post()  → a waiting thread can proceed


The semaphore prevents more threads from acquiring permits than are available.







Compile and run
gcc without_sem.c -o without_sem -pthread
./without_sem


Possible output:
Thread 1 is using resource
Thread 2 is using resource
Thread 1 finished
Thread 2 finished


Both threads can use the resource simultaneously. If the resource allows only one user at a time, this is incorrect.
Note: The code only simulates resource usage. Actual data corruption depends on what the threads do with the shared resource.







Compile and run
gcc with_sem.c -o with_sem -pthread
./with_sem


Possible output:
Thread 1 is using resource
Thread 1 finished
Thread 2 is using resource
Thread 2 finished


The order of the threads may be reversed, but their protected sections won't overlap because the semaphore starts with one permit.
In this example:
- sem_init(&sem, 0, 1) initializes a process-local semaphore shared by threads.
- sem_wait(&sem) acquires a permit.
- The thread uses the resource.
- sem_post(&sem) releases the permit.
- sem_destroy(&sem) destroys the semaphore after both threads finish.
For production code, check the return values of semaphore and pthread functions. If sem_wait() is interrupted by a signal, it can fail with errno == EINTR; handle that appropriately before accessing the protected resource.




7. Counting semaphore example
What if a resource has 3 available slots?
Change the initialization:
sem_init(&sem, 0, 3);


Now up to three threads can acquire permits concurrently. A fourth thread must wait until one of them calls sem_post().
Initial value	Maximum concurrent permit holders
1	1
2	2
3	3
5	5
This assumes each thread acquires one permit and releases it correctly.
8. Where are semaphores used? 🛠️
- Producer-consumer: Notify a consumer when items are available in a queue.
- Resource pools: Limit simultaneous use of connections or resource slots.
- Thread synchronization: Signal that one operation has completed.
- Embedded Linux: Coordinate work among application threads.
- Interprocess coordination: Use appropriately shared or named semaphores between processes.
For example, a producer can call sem_post() when it adds an item, while a consumer calls sem_wait() before removing an item. A mutex may also be needed to protect the queue itself.




9. Semaphore vs Mutex
Feature	Semaphore	Mutex
Main purpose	Signaling or permit counting	Mutual exclusion
Counter	Zero or more	Locked or unlocked state
Ownership	No mutex-style ownership	Has ownership
Resource limit	Can allow multiple permit holders	Usually one lock holder
Typical APIs	sem_wait(), sem_post()	pthread_mutex_lock(), pthread_mutex_unlock()
🎯 One-line definition
A semaphore is a synchronization mechanism that uses a counter to control resource access or coordinate threads and processes.
