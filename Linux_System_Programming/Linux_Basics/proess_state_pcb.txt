What is a Process State?

A process state represents the current execution condition of a process, such as running, sleeping, stopped, or zombie.

What is PCB?

PCB, or Process Control Block, is the kernel-maintained data associated with a process, containing information such as its PID, state, scheduling information, memory information, and other resources. 
In Linux, the main process descriptor is task_struct.

🟢 R — Running / Runnable

R means the process is running or ready to run.

Example:

while (1)
{
    // continuously doing work
}

The process may be actively using the CPU or waiting in the run queue for CPU time.

CPU
 │
 ▼
⚙️ Process
State = R
⚪ S — Interruptible Sleep

This is a very common state.

The process is waiting for something, such as:

Input
A signal
A timer
Another event

Example:

sleep(10);

During the sleep:

Process
   │
   ▼
😴 SLEEPING
   │
   │ 10 seconds
   ▼
🟢 Runnable

You can see it using:

ps -el
🟡 D — Uninterruptible Sleep

D generally means the process is waiting for an operation that cannot be interrupted normally, commonly certain kernel I/O operations.

For example, a process may be waiting for:

💾 Disk I/O
🔌 Device I/O

Conceptually:

Process
   │
   ▼
⏳ Waiting for I/O
   │
   ▼
D state

This state is especially important when troubleshooting processes that appear stuck.

🔴 T — Stopped

A process can be stopped by a signal or job-control operation.

For example:

./program

Then press:

Ctrl + Z

The process is stopped.

You can check:

ps

and may see:

T

To continue it in the background:

bg

Or bring it back to the foreground:

fg
🧟 Z — Zombie

You already learned this one. 😄

The process has finished execution, but its parent hasn't collected its termination status yet.

👶 Child
   │
   │ exit()
   ▼
🧟 ZOMBIE
   │
   │ wait()
   ▼
🧹 Reaped

ps may show:

Z

or:

<defunct>
⚫ I — Idle

I is mainly associated with idle kernel threads, rather than normal user applications.

You may encounter it when looking at Linux processes with tools such as:

ps

For basic Linux System Programming, focus mainly on:

R → Running/Runnable
S → Sleeping
D → Uninterruptible sleep
T → Stopped
Z → Zombie

3️⃣ What is PCB?

PCB = Process Control Block

The PCB is the kernel's data structure containing important information about a process.

Think of it like a record/file maintained by the operating system for each process.

Important Linux terminology

In Linux, the kernel's main per-process structure is called task_struct.

So when you hear:

"Linux PCB"

you should understand that Linux represents the process's kernel-side information primarily through struct task_struct and related structures.


1. 🆔 PID

Process ID:

PID = 5001

Used to identify the process.

2. 👨‍👦 Parent Information

The kernel keeps information about the process hierarchy.

Parent PID
Child relationships
3. 🔄 Process State

For example:

R
S
D
T
Z

The kernel needs to know what the process is currently doing.

4. 🧮 CPU Information

The kernel needs information required to resume the process.

For example:

CPU registers
Program counter
Stack information

This becomes important during context switching.

5. 🧠 Memory Information

The kernel tracks the process's memory-related information:

Code
Data
Heap
Stack
Virtual memory mappings
6. 📂 File Descriptors

A process may have:

0 → stdin
1 → stdout
2 → stderr
3 → file
4 → socket
5 → pipe

The kernel keeps track of the process's open files and other file descriptors.

7. ⚙️ Scheduling Information

The kernel needs information to decide:

"Which process should get CPU time?"

This includes scheduling-related information such as priority and scheduling policy.



🔄 PCB and Context Switching

This is one of the most important connections.

Suppose:

CPU
 │
 ▼
⚙️ Process A

The scheduler decides to run Process B.

Linux needs to preserve enough state for A so that it can resume later.

Conceptually:

Process A
   │
   │ Save state
   ▼
📋 Kernel process information
   │
   │ Load B's state
   ▼
Process B
   │
   ▼
CPU

This is called:

🔄 Context Switching

The kernel switches the CPU from one process/thread to another while preserving the necessary execution state.
