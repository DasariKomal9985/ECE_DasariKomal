6. Clock System ⏱️ — Embedded C
The Clock System is one of the most important concepts in Embedded C, especially when working with microcontrollers such as STM32.
A microcontroller clock provides timing signals that help the CPU execute instructions and peripherals perform operations at the required speed.
For example, the CPU, timers, UART, SPI, and I²C may use different clock frequencies derived from the main clock system.


1. Internal Clock 🕒
What is it?
An internal clock is a clock signal generated inside the microcontroller using its built-in oscillator circuitry. It allows the microcontroller to operate without requiring an external crystal.
Why is it used?
- Reduces external components.
- Simplifies hardware design.
- Provides a convenient clock source during startup.
- Can reduce hardware cost.
How does it work?
The microcontroller's internal oscillator generates a clock signal. The clock configuration circuitry can select this signal directly or use it as an input to a PLL, if supported.
Example: An STM32 can use its internal HSI clock as a source for the system clock.





2. HSI (High-Speed Internal) ⚡
What is it?
HSI stands for High-Speed Internal. It is a built-in high-speed clock source available in many STM32 microcontrollers.
Why is it used?
It provides a convenient clock source without needing an external crystal or oscillator.
How does it work?
The HSI oscillator generates a clock signal internally. Depending on the STM32 model, this signal may be used directly or passed through a PLL to generate a higher system clock frequency.
Example: Some STM32 microcontrollers have a 16 MHz HSI, while others use different frequencies. Always check the specific chip's datasheet.
Remember: HSI is a type of internal oscillator clock source.





3. Internal Oscillator 🔧
What is it?
An internal oscillator is an electronic circuit built into a microcontroller that generates a periodic signal used for clocking digital circuits.
Why is it used?
The CPU and peripherals need clock signals to coordinate their operations. An internal oscillator provides a clock source without requiring a separate external oscillator circuit.
How does it work?
The oscillator circuit produces a repeating electrical signal. The clock system uses this signal to provide timing to the CPU or other clock-generation circuits.
Where is it used?
- Microcontroller startup.
- Basic applications that do not require high clock accuracy.
- Low-power operating modes, depending on the oscillator.
- Generating a source clock for the PLL.





4. RC Oscillator 🔋
What is it?
An RC oscillator is an oscillator that uses resistance (R) and capacitance (C), along with active electronic circuitry, to generate a periodic signal.
Why is it used?
RC oscillators can be compact and inexpensive, making them useful for generating clocks without a crystal.
How does it work?
The resistor-capacitor network controls timing within the oscillator circuit. The circuit repeatedly charges and discharges capacitance or uses related feedback mechanisms to generate oscillations.
Advantages:
- Low cost.
- Small size.
- Can be integrated inside a chip.
Limitation: Its frequency is generally more sensitive to temperature, supply voltage, and component variation than a well-designed crystal-based reference.
Many internal microcontroller oscillators use RC-based designs.





5. Clock Accuracy 🎯
What is it?
Clock accuracy describes how closely an actual clock frequency matches its intended or specified frequency.
For example, if a clock is intended to operate at 8 MHz but actually operates at 8.08 MHz, its frequency error is 1%.
Why is it important?
Many embedded operations depend on accurate timing:
- UART communication.
- Timers and delays.
- Real-time clock functions.
- Communication protocols.
- Time measurement.
How does it work?
Every clock source has some amount of frequency error. That error can cause timing differences between devices or make a communication peripheral operate at a slightly different rate than expected.
Example: If the clock used to generate a UART baud rate is inaccurate, the actual communication baud rate may also be inaccurate.
Remember: Crystal oscillators generally offer better frequency accuracy and stability than many internal RC oscillators, although the exact performance depends on the components and design.




7. External Clock 🌐
What is it?
An external clock is a clock signal supplied to the microcontroller from outside its internal oscillator circuitry.
The signal may come from a crystal-based oscillator circuit or a separate clock generator.
Why is it used?
External clock sources can provide better accuracy, stability, or synchronization when the application requires them.
How does it work?
The external clock signal enters through a designated clock input or is generated by an external crystal circuit connected to the appropriate pins. The microcontroller's clock system can then use that source if configured correctly.
Example: An application requiring accurate UART timing may use an external crystal clock source.





8. HSE (High-Speed External) ⚙️
What is it?
HSE stands for High-Speed External. On many STM32 microcontrollers, it refers to the high-speed external clock source, commonly provided by a crystal/resonator circuit or an external clock signal.
Why is it used?
It provides an external reference clock that may offer better frequency accuracy than the internal HSI oscillator.
How does it work?
The microcontroller is configured to use the external high-speed clock source. Depending on the design, HSE can drive the system clock directly or serve as the input to a PLL.
Example: An STM32 board with an 8 MHz external crystal may use HSE as the input to a PLL to generate a higher system clock frequency.
Important: The available HSE configuration and supported frequency depend on the particular microcontroller and board.





9. Crystal Oscillator 💎
What is it?
A crystal oscillator is a clock-generating circuit that uses the mechanical resonance of a quartz crystal to produce a stable frequency.
Why is it used?
Quartz crystals provide a relatively accurate and stable frequency reference for applications requiring dependable timing.
How does it work?
The quartz crystal resonates at a particular frequency when used in an appropriate electronic oscillator circuit. The resulting electrical signal provides a clock reference to the microcontroller.
Where is it used?
- Microcontroller system clocks.
- UART and other communication timing.
- Real-time clock circuits when appropriate crystal frequencies are used.
- Systems requiring stable timing.
Example: A board may have an 8 MHz crystal connected to the STM32's HSE oscillator pins.
Remember: A crystal is a resonating component; it usually needs oscillator circuitry to produce the electrical clock signal.





10. External Clock Source 🔌
What is it?
An external clock source is a device or circuit outside the microcontroller that supplies a clock signal to it.
Examples include:
- An oscillator module.
- A clock generator IC.
- Another device supplying a suitable clock output.
- A crystal connected to the microcontroller's oscillator circuit, depending on how the clock-source terminology is used.
Why is it used?
It can provide a precise frequency, allow multiple devices to share a timing reference, or meet a specific system timing requirement.
How does it work?
The external device generates a clock waveform and supplies it to a supported clock input. The microcontroller must be configured for the appropriate external-clock mode.
Important distinction: A crystal used with an oscillator circuit and a ready-made external clock signal are not always configured in the same way.






11. Low-Speed Clock 🐢
What is it?
A low-speed clock is a relatively low-frequency clock source used for functions that do not require the main CPU's high-speed clock.
Why is it used?
It can support timekeeping and low-power operations while reducing power consumption compared with running high-speed clock circuitry.
How does it work?
A low-speed oscillator generates a slower clock signal. Depending on the microcontroller, it may be used by the RTC, watchdog, or other low-speed peripherals.
Example: An RTC may use a 32.768 kHz clock to keep track of seconds, minutes, and hours.
Remember: Low-speed does not automatically mean low-power in every configuration; power consumption depends on the oscillator and operating mode.





12. LSI (Low-Speed Internal) 🔋
What is it?
LSI stands for Low-Speed Internal. It is a built-in low-frequency oscillator available on many STM32 microcontrollers.
Why is it used?
It provides an internal low-speed clock for supported functions without requiring an external low-speed crystal.
How does it work?
The internal oscillator generates a relatively low-frequency clock. Depending on the device, it may clock an independent watchdog or provide a clock source for other supported peripherals.
Example: Some STM32 microcontrollers use LSI for the independent watchdog.
Limitation: LSI frequency accuracy is generally lower than that of a suitable external crystal, so it may not be appropriate for precision timekeeping.





13. LSE (Low-Speed External) 💎
What is it?
LSE stands for Low-Speed External. On many STM32 microcontrollers, it is an external low-speed clock source commonly associated with a 32.768 kHz quartz crystal.
Why is it used?
It provides an accurate, stable clock for timekeeping functions, often including the real-time clock (RTC).
How does it work?
A 32.768 kHz crystal is connected to the designated LSE oscillator pins. The microcontroller's LSE circuitry generates a clock signal from the crystal.
The frequency is useful because:
\[
32768 = 2^{15}
\]

This allows a circuit to divide the frequency by \(2^{15}\) to obtain one pulse per second.
Example: An STM32 RTC can use LSE to maintain time while the main CPU clock is stopped, provided the RTC and required backup/power circuitry remain powered.
Remember: LSE and LSI are different: LSE is external; LSI is internal.





14. PLL (Phase-Locked Loop) 🔄
What is it?
A PLL stands for Phase-Locked Loop. It is a clock-generation circuit that can multiply or otherwise synthesize frequencies from a reference clock, according to the microcontroller's supported configuration.
Why is it used?
The internal or external oscillator may run at a frequency lower than the desired CPU clock. A PLL can generate a higher clock frequency from that reference.
How does it work?
A simplified PLL clock path is:
1. Select a reference clock, such as HSI or HSE.
2. Configure the PLL's supported input division, multiplication, and output division settings.
3. Enable the PLL and wait for it to lock.
4. Select the PLL output as the system clock if the configuration supports it.
The exact formula and configuration depend on the microcontroller.
Example: An 8 MHz HSE source may be used with a PLL to generate a 72 MHz system clock on a microcontroller that supports that configuration.
Important: PLL setup must respect the device's maximum CPU, bus, and peripheral clock frequencies.





15. Frequency Multiplication 📈
What is it?
Frequency multiplication is the process of generating a clock frequency that is a multiple of a reference frequency.
Why is it used?
It allows a microcontroller to generate the faster clock rates needed for CPU execution and peripherals without requiring an external oscillator at that exact high frequency.
How does it work?
A PLL can use multiplication and division factors to produce its output frequency.
A simplified example:
\[
f_{\text{out}} = f_{\text{in}} \times N
\]

Here, \(N\) represents a multiplication factor in this simplified case. Real PLL configurations may also divide the input and output frequencies.
Example: If a supported PLL configuration multiplies a 8 MHz reference by 9, the output is 72 MHz.
Remember: Frequency multiplication does not mean that every clock in the microcontroller automatically runs at the multiplied frequency. Bus and peripheral clocks may be divided afterward.





16. System Clock Generation ⚡
What is it?
System clock generation is the process of selecting and configuring clock sources and clock-generation circuits to produce the clock used by the microcontroller's CPU and related system components.
Why is it used?
The system needs a suitable clock frequency for instruction execution, peripheral operation, timing, and power management.
How does it work?
A typical configuration might follow this sequence:
1. Start an internal or external oscillator.
2. Configure a PLL if a different frequency is needed.
3. Wait for the selected clock source or PLL to become ready.
4. Select the desired system clock source.
5. Configure bus prescalers and peripheral clock settings.
6. Confirm that all frequencies remain within the chip's limits.
Example: An STM32 application may start from HSI, configure the PLL, switch SYSCLK to the PLL output, and then set the AHB and APB prescalers.
Important: Correct configuration depends on the exact STM32 model and its clock-tree limits.





17. Clock Tree 🌳
What is it?
A clock tree is a diagram of how clock signals are generated, selected, divided, and distributed to the CPU, buses, and peripherals inside a microcontroller.
Why is it used?
Different components may require different clock frequencies. The clock tree helps engineers understand where each clock comes from and how its frequency is determined.
How does it work?
The clock tree typically contains:
- Clock sources such as HSI, HSE, LSI, and LSE.
- Clock selectors that choose between available sources.
- PLL circuits that generate other frequencies.
- Prescalers that divide clock frequencies.
- Bus clocks that feed the CPU and peripherals.
Example: In STM32CubeMX or STM32CubeIDE, the Clock Configuration view shows the clock sources, PLL settings, SYSCLK, HCLK, PCLK1, and PCLK2.
Remember: The clock tree is the complete clock-distribution structure, not a single clock signal.





18. SYSCLK (System Clock) 🖥️
What is it?
SYSCLK is the main system clock source selected for the microcontroller's system. In many STM32 families, it is selected from sources such as HSI, HSE, or a PLL output.
Why is it used?
It provides the main clock frequency from which the processor and bus clocks are derived.
How does it work?
The clock-control circuitry selects one of the available system clock sources. That selected frequency is called SYSCLK, and the clock tree distributes or divides it for other parts of the system.
Example: If SYSCLK is configured to 72 MHz, the AHB prescaler may be set to divide by 1, making HCLK 72 MHz as well.
Important: SYSCLK and HCLK are related, but they are not necessarily the same frequency.





19. HCLK (AHB Clock) ⚙️
What is it?
HCLK is the clock used by the AHB bus domain and associated system components. On many STM32 devices, it is also the clock used by the CPU core.
Why is it used?
It provides timing for the processor and system bus components that depend on the AHB clock domain.
How does it work?
HCLK is commonly derived by applying the AHB prescaler to SYSCLK.
\[
f_{\text{HCLK}} =
\frac{f_{\text{SYSCLK}}}{\text{AHB prescaler}}
\]

Example: If SYSCLK is 72 MHz and the AHB prescaler is 1, then HCLK is 72 MHz. If the prescaler is 2, HCLK becomes 36 MHz.
Remember: Always check the particular microcontroller's clock tree because CPU and bus clock arrangements differ across STM32 families.





20. PCLK1 (Peripheral Clock 1) 🔧
What is it?
PCLK1 is the peripheral clock associated with the APB1 bus domain on many STM32 microcontrollers.
Why is it used?
It supplies the clock to peripherals connected to APB1, such as certain UARTs, I²C controllers, timers, and other peripherals, depending on the chip.
How does it work?
PCLK1 is commonly derived by dividing HCLK using the APB1 prescaler.
\[
f_{\text{PCLK1}} =
\frac{f_{\text{HCLK}}}{\text{APB1 prescaler}}
\]

Example: If HCLK is 72 MHz and the APB1 prescaler is 2, PCLK1 is 36 MHz.
Important: Some STM32 timer clocks may run at a frequency different from PCLK1 when the APB prescaler is greater than 1. The exact rule is family-dependent.





21. PCLK2 (Peripheral Clock 2) 🔩
What is it?
PCLK2 is the peripheral clock associated with the APB2 bus domain on many STM32 microcontrollers.
Why is it used?
It supplies clock signals to peripherals connected to APB2. These may include certain USARTs, SPI peripherals, ADCs, and timers, depending on the device.
How does it work?
PCLK2 is commonly derived from HCLK through the APB2 prescaler.
\[
f_{\text{PCLK2}} =
\frac{f_{\text{HCLK}}}{\text{APB2 prescaler}}
\]

Example: If HCLK is 72 MHz and the APB2 prescaler is 1, PCLK2 is 72 MHz.
Remember: APB1 and APB2 can use different prescaler settings, so PCLK1 and PCLK2 do not have to be equal.





22. AHB (Advanced High-performance Bus) 🚌
What is it?
AHB stands for Advanced High-performance Bus. It is a bus architecture used in many ARM-based microcontrollers to connect high-performance system components.
Why is it used?
The CPU, memory, DMA, and other system components need a structured way to communicate. AHB provides a defined interface for transferring data and control information between supported components.
How does it work?
The AHB clock domain operates at HCLK on many STM32 devices. The bus carries read and write transactions between connected components according to the bus architecture.
Where is it used?
- CPU access to memory.
- DMA transfers.
- Access to internal system components.
- Communication between bus-connected components.
Example: A CPU reading data from SRAM uses the microcontroller's internal bus system.
Important: AHB is a bus architecture; HCLK is its associated clock signal. They are not the same thing.





23. APB1 (Advanced Peripheral Bus 1) 🔌
What is it?
APB1 is one of the peripheral bus domains in many STM32 microcontrollers. It connects supported peripherals through an Advanced Peripheral Bus interface.
Why is it used?
It provides a structured way to access peripherals that do not require the full performance of the main system bus.
How does it work?
The CPU or another bus master accesses an APB1 peripheral through the microcontroller's internal bus infrastructure. The APB1 peripheral clock is commonly called PCLK1.
Examples of peripherals that may use APB1:
- I²C controllers.
- Some USART/UART peripherals.
- Some timers.
- Other low- or moderate-speed peripherals.
The exact list varies by STM32 family.
Remember: APB1 is a bus domain, while PCLK1 is its clock.





24. APB2 (Advanced Peripheral Bus 2) 🔌
What is it?
APB2 is another peripheral bus domain used by many STM32 microcontrollers to connect supported peripherals.
Why is it used?
It organizes peripheral access and allows its clock frequency to be configured separately from APB1 where the device supports this arrangement.
How does it work?
The CPU accesses APB2 peripherals through the internal bus infrastructure. The APB2 peripheral clock is commonly called PCLK2.
Examples of peripherals that may use APB2:
- Certain SPI peripherals.
- Certain USART peripherals.
- ADC interfaces.
- Timers and other peripherals, depending on the chip.
Remember: APB2 peripherals are not necessarily faster than APB1 peripherals in every configuration; their clock frequency depends on the selected prescaler.





25. Prescalers ➗
What is it?
A prescaler is a clock-divider circuit that reduces an incoming clock frequency by a configured division factor.
Why is it used?
Not every component can or needs to run at the system clock frequency. Prescalers allow bus clocks and peripheral clocks to run at suitable frequencies.
How does it work?
A prescaler divides the input frequency by a supported value.
\[
f_{\text{out}} =
\frac{f_{\text{in}}}{\text{division factor}}
\]

Example: If HCLK is 72 MHz and the APB1 prescaler is 2, then PCLK1 is 36 MHz.
Where is it used?
- Dividing SYSCLK to generate HCLK.
- Generating APB bus clocks.
- Setting timer counter frequencies.
- Configuring peripheral timing.
Important: Clock prescaler choices must obey the maximum frequency allowed for each bus and peripheral.






26. Key Clock Flow 🔁
The overall flow you listed is a useful way to understand the clock system.
1. Clock Source
HSI · HSE · Other supported sources


2. PLL (Optional)
Generates a different frequency when configured and supported


3. SYSCLK
Selected system clock source


4. HCLK
SYSCLK divided by the AHB prescaler

PCLK1
APB1 prescaler



PCLK2
APB2 prescaler




Simplified STM32-style clock flow. Actual clock sources, dividers, and peripheral connections depend on the microcontroller.




Example clock calculation
Assume a microcontroller supports this configuration:
- HSE clock source = 8 MHz
- PLL multiplies the reference by 9
- AHB prescaler = 1
- APB1 prescaler = 2
- APB2 prescaler = 1
Then:
Clock	Calculation	Frequency
HSE	Reference clock	8 MHz
PLL output	8 × 9	72 MHz
SYSCLK	Selected PLL output	72 MHz
HCLK	72 ÷ 1	72 MHz
PCLK1	72 ÷ 2	36 MHz
PCLK2	72 ÷ 1	72 MHz




This is an illustrative example; make sure the selected STM32 model supports these settings.
Final revision points 📝
- HSI: High-speed internal clock.
- HSE: High-speed external clock.
- LSI: Low-speed internal clock.
- LSE: Low-speed external clock.
- PLL: Generates a configured clock frequency from a reference source.
- SYSCLK: Selected system clock source.
- HCLK: AHB/system clock domain frequency.
- PCLK1: APB1 peripheral clock.
- PCLK2: APB2 peripheral clock.
- Prescaler: Divides a clock frequency.
- Clock tree: Shows how clocks are generated and distributed.
