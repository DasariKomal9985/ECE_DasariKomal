19. Communication Protocols in Embedded Systems 🔌
Communication protocols define how two or more electronic devices exchange data. In embedded systems, a microcontroller communicates with sensors, displays, memory chips, other controllers, computers, and industrial equipment using different protocols.
For example, an STM32 microcontroller can communicate with:
- 🌡️ Temperature sensors using I²C.
- 💾 External memory or displays using SPI.
- 💻 A computer using UART or USB-to-UART.
- 🚗 Automotive electronic control units using CAN.
- 🏭 Industrial equipment using RS485.
Let's understand each topic step by step.







1. What is a Communication Protocol?
A communication protocol is a set of rules that specifies how data is transmitted and received between devices.
These rules define:
- How data is formatted.
- How devices identify each other.
- How fast data is transferred.
- How the sender and receiver synchronize.
- How errors are detected or handled.
Example: An STM32 sends the character A to a computer. Both devices must agree on the communication method, speed, and data format so the computer can correctly receive A.









2. UART — Universal Asynchronous Receiver/Transmitter 📡
UART is a serial communication method commonly used to transfer data between two devices.

Concept: the transmitter's TX connects to the receiver's RX, and the devices share a common ground.

How does UART work?
UART usually uses three connections:
- TX: Transmits data.
- RX: Receives data.
- GND: Common electrical reference.
The TX pin of one device connects to the RX pin of the other device, and vice versa for two-way communication.
UART is asynchronous because it does not use a separate clock wire. Both devices agree on a baud rate and use start and stop bits to identify each data frame.
Example
Suppose an STM32 sends HELLO to a computer through a USB-to-UART adapter.
The STM32 transmits the data through TX, and the adapter passes it to the computer.
Important UART parameters
Parameter	Meaning
Baud rate	Signaling speed, commonly 9600 or 115200
Data bits	Number of data bits, often 8
Parity	Optional error-detection bit
Stop bits	Indicate the end of a frame
TX/RX	Transmit and receive signals
A common configuration is 115200 baud, 8 data bits, no parity, 1 stop bit (8-N-1).
Where is UART used?
- Debugging embedded systems.
- Sending sensor readings to a computer.
- GPS modules.
- Bluetooth serial modules.
- Bootloaders and console interfaces.








3. SPI — Serial Peripheral Interface ⚡
SPI is a synchronous serial communication protocol commonly used for high-speed communication between a microcontroller and peripheral devices.

SPI typically uses a clock, two data lines, and a chip-select signal.

SPI signal lines
Signal	Meaning	Purpose
MOSI	Master Out, Slave In	Master sends data
MISO	Master In, Slave Out	Peripheral sends data
SCLK	Serial Clock	Synchronizes data transfer
CS/SS	Chip Select / Slave Select	Selects a peripheral
The terms master and slave are also called controller and peripheral in newer terminology.
How does SPI work?
1. The master selects a peripheral using CS.
2. The master generates the clock.
3. Data is shifted through MOSI and/or MISO.
4. The master ends the transfer by deasserting CS.
SPI can transmit and receive data simultaneously, making it a full-duplex protocol when both data lines are used.
Where is SPI used?
- External flash memory.
- TFT displays.
- High-speed ADCs.
- Sensors such as accelerometers.
- The MCP2515 SPI-to-CAN controller.
Example: An STM32 can use SPI to communicate with an MCP2515, which provides CAN communication capability.









4. I²C — Inter-Integrated Circuit 🧩
I²C is a synchronous serial communication protocol that allows multiple devices to share the same two signal lines.

I²C devices share SDA and SCL; pull-up resistors are generally required.

I²C signal lines
- SDA: Serial Data.
- SCL: Serial Clock.
How does I²C work?
1. The controller generates a START condition.
2. It sends the target device's address.
3. The selected device acknowledges the address when appropriate.
4. Data is transferred over SDA, synchronized by SCL.
5. The controller ends the transaction with a STOP condition.
Each device generally has an address, allowing several peripherals to use the same bus.
Where is I²C used?
- Temperature sensors.
- RTC modules.
- EEPROMs.
- Small displays.
- Environmental sensors.
Example: Your STM32 can read temperature from an LM75 sensor using I²C. If the LM75 uses address 0x48, the STM32 communicates with that device by addressing it on the bus.
UART vs SPI vs I²C
Feature	UART	SPI	I²C
Clock wire	No	Yes	Yes
Main signal wires	TX, RX	MOSI, MISO, SCLK, CS	SDA, SCL
Device addressing	Usually no built-in bus addressing	Usually selected by CS	Uses addresses
Typical arrangement	Point-to-point	Controller and peripherals	Shared bus
Duplex	Full duplex possible	Full duplex possible	Half duplex on SDA
Common use	Debug console	Fast peripherals	Sensors and RTCs












5. CAN — Controller Area Network 🚗
CAN is a robust communication protocol designed for multiple electronic controllers to exchange messages reliably, particularly in noisy environments.
It is widely used in automotive and industrial systems.
How does CAN work?
CAN devices share a bus, usually consisting of two wires:
- CAN_H: CAN High.
- CAN_L: CAN Low.
Instead of sending data to a specific device address in the same way as I²C, CAN messages carry an identifier that indicates the message's meaning and priority.
When multiple nodes begin transmitting together, CAN arbitration allows the highest-priority message to continue without corrupting the winning message.
CAN also provides error detection and mechanisms for handling transmission errors.
Example
In a vehicle:
- The engine controller sends engine-speed information.
- The dashboard receives the information and displays the speed.
- Other controllers can also receive that message if they need it.
Where is CAN used?
- Automotive ECUs.
- Industrial machinery.
- Robotics.
- Motor controllers.
- Medical and embedded control equipment.
CAN termination
A conventional high-speed CAN bus generally uses a 120-ohm termination resistor at each physical end of the bus. Correct termination helps prevent signal reflections.
Embedded example: The STM32F401RBT6 does not have a built-in CAN peripheral. You would need a suitable external CAN controller, such as the MCP2515, plus a CAN transceiver. Some other STM32 models have integrated CAN peripherals.












6. RS232 🔌
RS232 is a serial electrical interface standard often used for communication between computers, industrial devices, and legacy equipment.
It defines electrical signaling characteristics and interface behavior; UART is a way of generating and receiving the serial data format commonly used with it.
How does RS232 work?
RS232 uses voltage levels different from typical 3.3 V or 5 V microcontroller UART logic.
For that reason, you should not directly connect an RS232 signal to an STM32 UART pin. An RS232 transceiver, such as a MAX3232, converts between RS232 voltage levels and logic-level UART signals.
Where is RS232 used?
- Older computer serial ports.
- Industrial instruments.
- Configuration and debugging ports.
- Legacy communication equipment.
Important: UART and RS232 are not the same thing. UART describes the serial data framing and transmission/reception function; RS232 describes the electrical interface.













7. RS485 🏭
RS485 is an electrical interface standard designed for robust serial communication, including communication over long cables and in electrically noisy industrial environments.
It commonly uses differential signaling over two wires.
How does RS485 work?
The transmitter sends a voltage difference between two wires. The receiver interprets that difference as a logical signal.
RS485 is often used in multidrop networks, where multiple devices share one bus. A common two-wire RS485 arrangement is half duplex, meaning devices take turns transmitting and receiving.
RS485 does not define the complete message protocol. A protocol such as Modbus RTU is often used over RS485.
Where is RS485 used?
- PLCs and industrial automation.
- Variable-frequency drives (VFDs).
- Energy meters.
- Building management systems.
- Long-distance sensor networks.
RS232 vs RS485
Feature	RS232	RS485
Signaling	Single-ended	Differential
Typical wiring	Separate TX and RX signals plus reference	Often a two-wire shared bus
Multiple devices	Usually point-to-point	Supports multidrop networks
Noise immunity	Lower in typical installations	Better in typical industrial installations
Typical application	Legacy serial equipment	Industrial communication














8. Synchronous vs Asynchronous Communication ⏱️
These terms describe how the sender and receiver keep data timing aligned.
Synchronous communication
The devices use a shared or transmitted clock to synchronize data transfer.
Examples:
- SPI
- I²C
How it works: The clock indicates when data should be sampled or shifted.
Asynchronous communication
The data transfer does not use a separate clock signal shared between the devices. Instead, the devices agree on timing settings and use framing or other mechanisms to identify data boundaries.
Examples:
- UART
- Common UART-based serial links such as RS232
Feature	Synchronous	Asynchronous
Separate clock	Typically yes	No shared clock wire in UART
Timing	Coordinated by clock	Agreed timing and frame boundaries
Examples	SPI, I²C	UART
Wiring	Often includes a clock line	Often TX and RX
Note: The synchronous/asynchronous distinction is about timing. It is separate from whether communication is full duplex or half duplex.














9. Serial vs Parallel Communication 🔄
Serial communication
Data bits are transmitted sequentially over one or a small number of data lines.
Examples: UART, SPI, I²C, CAN.
Advantages:
- Fewer wires.
- Easier cabling over longer distances.
- Often simpler connectors and routing.
Parallel communication
Multiple data bits are transmitted simultaneously over multiple data lines.
For example, an 8-bit parallel interface can transfer eight data bits at once, using eight data wires plus any required control signals.
Advantages:
- Can transfer many bits per transfer cycle.
- Useful for certain short-distance, high-throughput interfaces.
Challenges:
- Requires more wires and pins.
- Timing skew between lines can become a problem at higher speeds or longer distances.
Feature	Serial	Parallel
Data transmission	Sequential bits	Multiple bits together
Data lines	Fewer	More
Wiring	Simpler	More complex
Example	UART	8-bit parallel display interface













10. Full Duplex Communication ↔️
Full duplex means two devices can transmit and receive data at the same time.
For example, a telephone conversation allows both people to speak and hear simultaneously.
In embedded systems, UART commonly supports full duplex through separate TX and RX lines. SPI can also operate in full duplex using MOSI and MISO.
Example: An STM32 sends a command to a device while receiving data from it at the same time, if the protocol and peripheral support it.
11. Half Duplex Communication ↔️
Half duplex means devices can transmit in both directions, but not simultaneously on the same communication channel.
For example, walkie-talkies allow one person to speak at a time.
A typical two-wire RS485 bus is half duplex:
1. Device A transmits.
2. Device A stops transmitting.
3. Device B transmits its response.
The transmitter-enable and receiver-enable controls must be managed correctly to avoid two devices driving the bus at once.
12. Simplex Communication ➡️
Simplex means data flows in only one direction.
One device transmits, and the other receives; the receiver does not send data back through that same communication path.
Examples:
- A broadcast transmitter sending information to receivers.
- A one-way sensor output where the receiving controller never sends a response.
Duplex comparison
Mode	Direction	Simultaneous two-way transfer?	Example
Simplex	One direction only	No	One-way broadcast
Half duplex	Both directions, one at a time	No	Two-wire RS485
Full duplex	Both directions	Yes	Full-duplex UART











13. Differential vs Single-Ended Signaling ⚡
These terms describe how electrical signals represent information on wires.
Single-ended signaling
A signal is represented by the voltage of one signal wire relative to a reference, usually ground.
Examples include ordinary microcontroller UART TX/RX logic and many GPIO signals.
Advantages:
- Simple hardware.
- Fewer wires.
- Low cost.
Limitations:
- Noise or ground-voltage differences can affect the received signal.
Differential signaling
A signal is represented by the voltage difference between two wires.
For example, a receiver looks at the difference between line A and line B rather than relying on either wire's voltage relative to ground alone.
If external noise affects both wires similarly, the receiver can reject much of that common-mode noise.
Examples:
- CAN
- RS485
- RS422
- USB uses differential pairs for its data signaling.
Comparison
Feature	Single-ended	Differential
Signal reference	Signal voltage relative to ground	Voltage difference between two wires
Wires per signal	Usually one signal wire plus reference	Usually a pair of signal wires
Noise immunity	Generally lower	Generally higher
Common examples	GPIO, logic-level UART	CAN, RS485
Practical example: An STM32 UART pin operates at logic-level voltage. If you need to send data over a long, noisy industrial cable, you might connect the UART to an RS485 transceiver, which converts the logic-level signals into differential bus signals.















14. How these concepts fit together in a real embedded project 🛠️
Imagine an STM32-based industrial monitoring system:
- A temperature sensor sends readings over I²C.
- An external display communicates over SPI.
- A computer receives debugging messages over UART.
- A MAX3232 connects the UART to an RS232 device.
- An RS485 transceiver connects the STM32 to a PLC using Modbus RTU.
- A CAN controller and transceiver connect the system to a CAN bus.
