What is Memory Layout?
Definition: Memory layout describes how a compiled program is divided into different memory sections and how those sections are placed into physical memory such as Flash and SRAM.

A typical embedded C program has these sections:

Section Purpose Memory
.text Executable instructions Flash
.rodata Read-only constants Flash
.data Initialized global/static variables SRAM at runtime
.bss Uninitialized or zero-initialized global/static variables SRAM
Heap Dynamic memory allocation SRAM
Stack Local variables and function calls SRAM


#include <stdio.h>

static int static_global = 300;

{
    int local_var = 10;

    if (ptr != NULL)
    {
        *ptr = 500;

        free(ptr);
    }
}

int main(void)
{
    int a = 10;

 .text Section – Code Storage

Definition: The .text section contains the executable machine instructions generated by the compiler.

In our program, these functions have executable instructions:
void my_function(void)
{
    // Function instructions
}

int main(void)
{
    // Main function instructions
}
Where are they stored?
For STM32:
Flash Address: 0x08000000 onwards
The compiler converts these C statements into machine instructions, and the linker places the executable code in the .text section.

Important:

main() is stored in .text.
my_function() is stored in .text.
Other compiled functions are also normally stored in .text.

The CPU executes these instructions from Flash in a typical STM32 configuration.







.rodata Section – Read-Only Data
Definition: .rodata stores constant data that should not be modified during normal program execution.
In our code:

const int constant_var = 200;

Flash memory

String literals are also commonly placed in .rodata.
The string "Hello Embedded" is typically stored in .rodata, while the instructions for calling printf() are stored in .text.
Remember: const does not universally guarantee Flash placement in every C implementation. Actual placement depends on the compiler, linker and target.











 .data Section – Initialized Global and Static Variables
Definition: The .data section contains initialized global and static variables that can be modified during program execution.

From our code:
int global_init = 100;
static int static_global = 300;

And:
static int count = 5;

All three are initialized global/static variables.
Where are they stored?
But there is an important point!
Their initial values are stored in Flash before execution. During startup, the startup code copies those initial values from Flash into SRAM.

For example:

FLASH:
Initial value = 100

        |
        | Startup code copies
        v

SRAM:
global_init = 100

Why?
Because these variables need to be writable during program execution.

For example:
global_init++;

The updated value is maintained in SRAM, not by rewriting Flash.

Remember:
Initial values → Flash.
Actual runtime variables → SRAM.
This is the .data section.











 .bss Section – Uninitialized Global and Static Variables
Definition: The .bss section contains global and static variables that are uninitialized or explicitly initialized to zero.

From our code:
int global_uninit;
This variable belongs to .bss.
Example:
int global_uninit;

Although you did not initialize it, C guarantees that a global variable is initialized to zero.

During startup:
The startup code identifies the .bss memory range.
It initializes that region to zero.
The program starts executing main().

Example:
SRAM:
global_uninit = 0
