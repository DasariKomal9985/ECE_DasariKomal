What is Memory Architecture?
Definition: Memory architecture describes how memory is organized and used in a computer or microcontroller to store program instructions, data and intermediate results during execution.

A processor needs memory for two major purposes:

Program storage: Stores the firmware instructions.
Data storage: Stores variables, temporary data, stack, heap and other runtime information.

For embedded systems, the important memory types are:

RAM (Random Access Memory)
ROM (Read Only Memory)
SRAM (Static RAM)
DRAM (Dynamic RAM)
Flash Memory
EEPROM (Electrically Erasable Programmable ROM)












RAM (Random Access Memory)

Definition: RAM is a volatile memory that temporarily stores data and instructions required by the processor during program execution. Its contents are lost when power is removed.

Characteristics:

Volatile memory.
Read and write operations.
Fast access.
Used for temporary data storage.
Data is lost when power is switched OFF.

Example:
int a = 10;
int b = 20;
int c = a + b;

When this program executes, variables and intermediate data are handled using RAM and CPU registers, depending on compiler optimization and variable placement.

Important: RAM is a general category. SRAM and DRAM are two major types of RAM.














ROM (Read Only Memory)

Definition: ROM is a non-volatile memory used to store data or instructions that must be retained even when power is removed.

Characteristics:

Non-volatile memory.
Retains data without power.
Traditionally designed for read-only operation.
Used for permanent firmware or fixed data.

Types of ROM:

Type          Meaning
Mask ROM      Programmed during manufacturing
PROM.         Programmable once
EPROM         Erased using ultraviolet light
EEPROM        Electrically erasable and programmable

Important: Modern embedded microcontrollers commonly use Flash memory instead of traditional ROM because Flash can be electrically erased and reprogrammed.












SRAM (Static RAM)
Definition: SRAM is a type of volatile RAM that stores each bit using a flip-flop-based circuit and retains data as long as power is supplied, without requiring periodic refreshing.

Characteristics:

Volatile memory.
Very fast.
No refresh operation required.
More expensive per bit.
Requires more chip area per bit.
Commonly used as CPU cache and microcontroller working memory.

Example: STM32F401

The STM32F401RB has:
128 KB Flash memory.
64 KB SRAM.

When your firmware runs, SRAM is used for:

Global variables.
Local variables.
Stack.
Heap (if dynamically allocated).
Temporary runtime data.












DRAM (Dynamic RAM)
Definition: DRAM is a type of volatile RAM that stores each bit using a capacitor and transistor. Since the capacitor gradually loses its charge, DRAM requires periodic refreshing to retain data.

Characteristics:

Volatile memory.
Requires periodic refresh.
Higher storage density than SRAM.
Generally cheaper per bit.
Slower and more complex to manage than SRAM.
Commonly used as main memory in computers.

Example:
Your laptop might have 8 GB or 16 GB DDR4/DDR5 DRAM.
DDR4 and DDR5 are types of DRAM.









Flash Memory
Definition: Flash memory is a non-volatile memory that stores program instructions and data even when power is switched OFF. It can be electrically erased and reprogrammed.

Characteristics:
Non-volatile memory.
Retains data without power.
Electrically erasable and programmable.
Used to store embedded firmware.
Generally slower to write and erase than SRAM.
Erased in sectors or pages, depending on the device.
Supports a limited number of erase/program cycles.

Example: STM32F401RB
Memory Size Purpose
Flash 128 KB Firmware storage
SRAM 64 KB Runtime data storage

When you upload your firmware to STM32, it is generally stored in its internal Flash memory.

#include <stdint.h>

int main(void)
{
    int a = 10;
    int b = 20;
    int c = a + b;

    while (1)
    {
    }
}

The compiled machine instructions are stored in Flash. The runtime variables may be stored in SRAM or registers, depending on their scope and compiler optimization.











Therefore, SRAM is used for frequently changing runtime data.

What is Flashing?
Definition: Flashing is the process of programming firmware or other data into the non-volatile Flash memory of a microcontroller or embedded device.

Step-by-step process:

Writing: You write C source code.
Compilation: Compiler converts C code into machine instructions.
Linking: Linker combines object files and libraries and assigns memory addresses.
Generating firmware: An ELF file is generated; commonly a HEX or BIN file is also produced.
Flashing: ST-Link sends the firmware to STM32 Flash memory.
Execution: After reset, the processor starts executing the firmware through its reset vector.

Section Contains Typical location
.text Executable instructions Flash
.rodata Read-only constants and string literals Flash
.data Initialized global/static variables SRAM at runtime
.bss Uninitialized/zero-initialized global/static variables SRAM
Heap Dynamic memory allocation SRAM
Stack Local variables, function calls, return addresses SRAM


There is an important detail here.
The initialized .data section has two locations:
Its initial values are stored in Flash.
At startup, those initial values are copied into SRAM.
Similarly, the .bss section occupies SRAM and is initialized to zero during startup.


Power is supplied to the microcontroller.
CPU performs reset.
CPU reads the initial Stack Pointer value and Reset Handler address from the vector table.
Startup code executes.
Initialized global/static variables (.data) are copied from Flash to SRAM.
Uninitialized global/static variables (.bss) are initialized to zero.
System initialization happens.
main() is called.
Your application executes.


Important: The CPU does not normally copy the entire program from Flash into SRAM. On a typical STM32 Cortex-M4, it executes instructions directly from Flash using the memory-mapped Flash interface.
This is called Execute In Place (XIP).


1. Cache Memory
Very fast memory that stores frequently accessed instructions or data to reduce access time. Common in application processors; some Cortex-M processors also have caches.
2. CPU Registers
Very small, very fast storage locations inside the CPU. Used for operands, addresses, intermediate results and processor state.
3. Memory-mapped I/O
Peripheral registers are assigned specific memory addresses, allowing the CPU to control GPIO, UART, SPI, timers and other peripherals through memory reads and writes.
4. Stack Memory
Stores local variables, function call information, return addresses and saved registers.
5. Heap Memory
Used for dynamic memory allocation using functions such as malloc() and free().
6. OTP Memory
One-Time Programmable memory. Once programmed, its contents cannot normally be changed.
7. Backup SRAM
A special SRAM region available on some microcontrollers that can retain its contents during certain low-power conditions if the backup power domain remains powered.

Flash Memory – NOR vs NAND
Flash memory has two major architectures.
A. NOR Flash
Definition: NOR Flash is non-volatile memory that supports random access to stored data and is commonly used for storing executable firmware.
Characteristics:
Non-volatile.
Supports random reads.
Suitable for executing code directly (XIP).
Erasing is performed in sectors.
Commonly used for boot firmware and microcontroller program storage.
Examples:
STM32 internal Flash.
External QSPI NOR Flash.
SPI NOR Flash.



NAND Flash
Definition: NAND Flash is non-volatile memory designed for high-density data storage, commonly used in SSDs, eMMC, USB drives and memory cards.
Characteristics:
Non-volatile.
High storage density.
Lower cost per bit at high capacities.
Read/write operations happen in pages.
Erasing happens in blocks.
Requires management of bad blocks and error correction.




. What is eMMC?
Definition: eMMC (Embedded MultiMediaCard) is a non-volatile storage device that combines NAND Flash memory and a dedicated Flash Memory Controller in a single package.

In simple words:
eMMC = NAND Flash + Flash Controller.
The controller manages:
Bad block management.
Wear leveling.
Error correction (ECC).
Logical-to-physical address translation.
Flash management.

Why do we need eMMC?
Consider an embedded Linux board.
It needs to store:
Bootloader.
Linux kernel.
Device tree.
Root filesystem.
Applications.
Configuration files.
User data.


SRAM is too small and volatile for this purpose.
eMMC provides persistent storage for all these components.
How does eMMC work?
The processor communicates with eMMC using the MMC protocol, commonly through an SD/MMC host controller.
The operating system accesses the storage as a block device.

lsblk

NAME        SIZE TYPE MOUNTPOINTS
mmcblk0     16G  disk
├─mmcblk0p1 128M part /boot
└─mmcblk0p2  15G part /




Here:
mmcblk0 = eMMC or SD/MMC block device.
mmcblk0p1 = First partition.
mmcblk0p2 = Second partition.
Note: mmcblk0 does not automatically mean eMMC. It can also be an SD card. You need to identify the actual hardware.


What happens when you power ON BeagleBone?
A simplified boot sequence:
ROM boot code executes inside the processor.
Bootloader is loaded from a boot source, such as eMMC or microSD.
Bootloader initializes DDR memory.
Linux kernel is loaded into DDR RAM.
Kernel initializes hardware and drivers.
Root filesystem is mounted from eMMC or SD card.
Linux starts systemd or another init system.
Applications start executing.
